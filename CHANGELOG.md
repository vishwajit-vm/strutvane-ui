# @strutvane/ui

## 0.2.0-next.0

### Minor Changes

- 5e5023d: Add the app shell: `<StrutvaneApp>` (sign-in, workspace switcher, menu, list/create/detail/edit routes for every resource, app routes, 401 handling, default themable styles), plus `ResourceDetail`, `SignIn`, a small router (`Router`, `Link`, `useRouter`, `matchPath`, `RouteDefinition`), `createSessionClient` in the core, and an `onView` action on `ResourceList`.
- 399e81d: **v2 (breaking, the 0.2 line): behaviour only, drawn by a design.** Read `docs/migrating-from-v1.md`.
  
  - **The Design contract** (`@strutvane/ui/design`): `defineDesign()` with typed slots (shell, sixteen skins, four illustrations), light and dark colour tokens, sizes, fonts and a chart palette; the public override tokens `--brand-hue`, `--font-sans`, `--radius` and `--density`; `<DesignProvider>` with a `nonce` for the injected stylesheet, a remembered light/dark/system theme and a CSP-hashed pre-paint theme script.
  - **The plain design** (`@strutvane/ui/design/plain`): the neutral fallback, passing its own conformance suite.
  - **The conformance kit** (`@strutvane/ui/testing`): `designConformance()` checks every slot, WCAG AA contrast for every token pair in both themes and at every brand hue, no hard-coded colours, the override tokens, no overflow at 375 px, and axe on nine reference screens of the real app.
  - **Conveniences:** Back with restored list state, breadcrumbs, the command palette, keyboard shortcuts (never while typing), filter chips with Clear all, column and density preferences, undo delete, type-to-confirm for permanent deletes, the unsaved-changes guard, sign in again on a 401 that keeps the draft, toasts.
  - **Lists:** numbered pages, 25 rows by default (10/25/50/100), never above the resource's `maxPerPage`; `page[number]` in URLs.
  - **Safety:** `X-XSRF-TOKEN` on every write; reads retried on no answer or a 5xx, writes never; 422 issues read `path`, then `field`; a clear `write_cancelled` message; problem codes matched in any case.
  - **Manifest:** reads `maxPerPage`, `routeKey` (`/posts/hello-world` URLs), `ui.order` and `ui.badge` when present (RFC-0005, proposed).
  - **Packaging:** `@strutvane/framework` is now a required peer (`@strutvane/framework/contracts` replaces `@strutvane/contracts`); Node `>=24.3`; built and published with npm.
  - **Removed:** `APP_STYLES` and the `styles` prop; `confirmDelete` (use `deletable`); the cursor list API (`nextPage`, `previousPage`, `hasPrevious`, `ListPageState`).

### Patch Changes

- 873cea6: Default app styles declare `color-scheme: light dark`, so in dark mode the browser draws native controls (select option lists, the date and datetime pickers, scrollbars) dark too, instead of light popups and dark-on-dark picker icons inside the dark theme.
- 3a1d3e4: Sign-out only shows the sign-in screen once the server confirmed it (or answered 401 because the session was already gone). A failed sign-out (offline, 5xx) now keeps the user signed in with the message "Could not sign out. You are still signed in; please try again." instead of hiding a still-valid session behind the sign-in screen. New catalog key: `ui.app.signOutFailed`.
- 9b093eb: A cell or widget that throws while rendering (an app override, an unknown field type, a value of an unexpected shape) no longer blanks the whole screen. Each list cell and detail field shows "Cannot display this value", and each form field shows "This field cannot be displayed. The other fields can still be saved."; everything else keeps working, and a cell retries when its value changes. New export: `RenderBoundary`; new catalog keys `ui.cell.error` and `ui.form.widgetError`.
- 8b92de4: Datetime fields (`type: "datetime"` / `"timestamp"`) get a widget and a cell. They fell back to a plain text input showing the raw UTC text (`2026-11-14T08:30:00.000Z`), and a time typed without an offset was refused by the API; cells showed the raw ISO text. `DateTimeWidget` is a native `datetime-local` input in the viewer's time zone that sends an ISO-8601 instant in UTC; `DateTimeCell` formats the instant in the viewer's time zone and keeps the exact value in `<time dateTime>`. New exports: `DateTimeWidget`, `DateTimeCell`, `toLocalInput`, `fromLocalInput`.
- da53cf6: `DecimalCell` (decimal and money values) shows at least two fraction digits and never fewer than the value has. A `decimal(12,4)` value such as `"1.2345"` was displayed as `1.23`, hiding the stored value and making different values look identical.
- e25f8e2: `<ResourceDetail>` deletes once per user action. A second click while the confirmation or the request was pending sent another `DELETE` (and showed "no longer exists" for a record that was just deleted), and every attempt used a new idempotency key. The Delete button is now disabled while a delete is pending, and the key is reused until the delete succeeds, like the list's Delete.
- 51aa428: Filter values now follow the server's rules exactly, so a filter the UI accepts is the filter the server applies. Decimal, money and big-integer values stay exact text (`9007199254740993` was sent as `9007199254740992`, `12345678901234567.89` was rounded, `1e21` was sent as `1e+21` and refused); datetime values must be ISO-8601 with an offset (zone-less text such as `Nov 14 2026` was sent and refused); text values are limited to 200 UTF-16 code units, as the server counts them. Applies to the filter bar and to filters read from the URL.
- eac0002: List URLs: a `search` value the server refuses (over 200 UTF-16 code units, or containing NUL) is now dropped and reported like any other bad parameter instead of being sent and failing the whole list with a 422, and the search box is limited to 200 characters. A page opened by link (a `page[cursor]` in the URL, no history) can now go back to page 1 with "Previous page" instead of being stuck.
- 03d3f3e: JSON fields (`type: "json"`) get a JSON widget and cell. They were edited in a plain text input, so saving sent the typed text as a JSON string, which the API accepts, silently replacing an object with a string; the detail page showed an empty dash. The new `JsonWidget` parses the text and sends the JSON value, refuses text that does not parse ("Value must be valid JSON.", catalog key `invalid_json`) and keeps the draft while typing; `JsonCell` shows the JSON. New exports: `JsonWidget`, `JsonCell`, and `InvalidJsonText` from `@strutvane/ui/core`.
- 4364fe9: `<ResourceList>` (and `useListQuery`) follow URL changes made outside the list. The URL was read only at mount, so clicking the menu entry of the list you were on, or Back/Forward between two states of the same list, changed the address bar while the list kept its old filters, sort and search. A new `initialSearch` that differs from the state the list reported now resets the list (search box included); the URL the list reported itself changes nothing. `useListQuery` returns a new `generation` counter that increases on each such reset.
- 19fae94: Relation collections (`hasMany`, `hasOne`, `manyToMany`), which the framework's manifest lists as fields but which have no value on the record, are no longer shown as an always-empty list column or as an empty read-only input in edit forms. The detail page keeps rendering them as related lists. An explicit `ui.listColumns` entry is still honoured.
- 291cfba: Accessibility: `<StrutvaneApp>` moves focus to the main area when the page changes (menu link, Open, Edit, Save, Back/Forward), so keyboard and screen-reader users land on the new content instead of on a link or button that may no longer exist. The first load and list query changes (filters, sort, paging) do not move focus.
- ce93dd3: App-shell routing fixes. Record ids are decoded from the URL once, so an id with spaces, slashes or non-ASCII characters reaches the API encoded once instead of twice (`a%2520b`, a 404); a malformed encoding shows "not found". Resource paths from the manifest are stored without surrounding slashes, so a path such as `/partners` can no longer turn a menu link into a protocol-relative link to another site (`//partners`), and multi-segment paths (`admin/accounts`) are routed instead of showing "not found".
- a98d518: `<ResourceForm>` sends one submission at a time. A second submit while the first request was in flight (Enter pressed twice, a fast double click, a script) used to send another create or update; since the API does not deduplicate the `Idempotency-Key`, a double create made two records. Further submits are ignored until the first one settles; after an error the form can be submitted again.
- efaf12e: Decimal and big-integer values exchanged as strings (`"1250.50"`, schema `type: "string"`) are shown by the number cells instead of an empty dash, and the number widget sends them back as exact text instead of a JavaScript number the API refuses. The default app styles use zero-specificity `:where()` selectors, so app CSS overrides them without workarounds.
- 920c811: Default app styles: a wide table now scrolls sideways inside the main area at every screen width. The rule existed only below 720px, so on desktop a table with many or long columns pushed the whole page, header and menu included, sideways.
- b69f0b1: A workspace switch the server refuses or that fails (403, offline, 5xx) now shows "Could not switch the workspace. Please try again." in the header instead of failing silently with an unhandled promise rejection, and the automatic selection of a user's only workspace is attempted once per workspace. New catalog key: `ui.app.switchFailed`.

## 0.1.0-next.0

### Minor Changes

- First implementation of the renderer core (Phase 1, ADR-0014):
  
  - `@strutvane/ui/core` (framework-free): manifest client with defensive validation, the ADR-0011 list-query URL format (repeated keys) and its `POST /query` fallback, the one filter builder, the list-state reducer with a cursor stack, client validation from the manifest, issue routing (deepest field → parent → banner), problem handling that never crashes on malformed responses, a small safe ICU-style message formatter, typed widget/cell registries, a batched record loader for relation labels, and a `fetch` client with idempotency keys.
  - `@strutvane/ui/react`: `<StrutvaneProvider>`, `<ResourceList>` (TanStack Table v9, server-side sort/filter/search/cursor pagination, URL deep links, virtualization above 100 rows with a fail-safe window, capability-gated New/Edit/Delete), `<ResourceForm>` (TanStack Form, widgets per field type, a searchable paginated belongsTo picker, client + server validation incl. array paths, focus management, idempotent retries), `<FieldShell>`, `<FilterBar>` and L1/L2 overrides through the provider.
